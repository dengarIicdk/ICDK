## 1. Продуктовое видение (TL;DR)

**WIBE CHANGER** — «Steam-мастерская на минималках» для косметики: пользователь открывает приложение, видит сетку героев, выбирает героя, листает карусель моделей (арканы, персоны, сеты, кастомные паки), смотрит **3D-превью прямо в приложении**, нажимает одну кнопку — и в следующем запуске Dota 2 герой выглядит иначе. Только у него на экране. В рейтинге, в турбо, в обычных — где угодно, потому что это подмена локальных файлов, а не вмешательство в игру.

Три кита продукта:

1. **Красиво** — премиальный тёмный интерфейс «кузница»: медные акценты, стекло, живые 3D-модели, плавные переходы. Не «консольная утилита с кнопкой».
2. **Безопасно** — приложение физически не умеет делать то, за что банят: не правит `gameinfo.gi`, `gameinfo_branchspecific.gi`, `dota.signatures`, не грузит DLL в `dota2.exe`, не меняет `items_game.txt` для «выдачи» предметов, не трогает карту/туман/деревья.
3. **Надёжно** — каждый мод = один `.vpk` + манифест; конфликты файлов видны заранее; после патча Dota всё восстанавливается одной кнопкой; «Откатить всё» возвращает ванильную игру побайтово.

### Ключевое техническое озарение

Dota 2 не проверяет содержимое визуальных ассетов. Она просто берёт **первый найденный файл по пути**. Сервер присылает клиенту только *путь* к модели (`models/heroes/axe/axe.vmdl`); байты по этому пути клиент читает у себя. Поэтому:

> Замена модели = положить другой скомпилированный `.vmdl_c` по тому же пути в VPK, который монтируется раньше ванильного.

Проверено: распаковали модель арканы Axe, переименовали в `axe.vmdl_c`, упаковали в VPK — VPK валиден, модель читается по новому пути (раздел 2.5).

Дефолтные слоты героя прописаны в `scripts/items/items_game.txt` (11 368 вхождений `model_player`), и они указывают на `models/heroes/<hero>/<hero>_<slot>.vmdl`. Это значит: **чтобы «снять» дефолтную броню/шлем, достаточно подменить эти пути нуль-моделью** — без правки схемы предметов.

### 2.4 Модель: что внутри и почему подмена работает

`models/heroes/axe/axe.vmdl_c` декомпилируется в текстовый `axe.vmdl` (78 файлов: vmdl + dmx) со структурой:

- `RenderMeshFile` → список мешей (+ LOD);
- `MaterialGroupList` → материалы (`materials/models/heroes/axe/*.vmat`);
- `AttachmentList` → точки крепления (`attach_mouth`, `attach_axe_head`, ...);
- `AnimationList` → **81 `AnimFile`** у полной модели (аркана/персона).

Вывод: **полные модели (арканы/персоны) самодостаточны** — анимации внутри, пути материалов уже есть в базовом паке. Поэтому их можно ставить на место базовой модели без пересборки, без `resourcecompiler` и без исходников.

### 2.6 VPK, который делает Source2Viewer, совместим с установленным модом

Заголовок нашего VPK и рабочего `pak64_dir.vpk` из `game/dota_russian`:

```
pak64 : 34 12 AA 55 | version 2 | archiveMD5 0 | otherMD5 0 | signature 0
наш   : 34 12 AA 55 | version 2 | archiveMD5 56 | otherMD5 48 | signature 20
```

Обе — Source 2 VPK версии 2 (магия `0x55AA1234`). Наш дополнительно содержит MD5-секции и подпись — это допустимо: движок читает и те, и другие.

### 2.7 Почему НЕЛЬЗЯ править `gameinfo.gi`

`game/dota/bin/win64/dota.signatures` содержит SHA1+CRC списка файлов, которые клиент проверяет:

```
...\dota\gameinfo.gi~SHA1:A0DC87ACC7A659EEDD1F9575EEE2BD3883E8F201;CRC:069ACF0D
...\dota\gameinfo_branchspecific.gi~SHA1:224B6F879D00D419B6A10FE07B4DDB3D827FD31F;CRC:7B89F784
...\dota\bin\win64\client.dll  ... server.dll ... host.dll ... modtools.dll ...
```

Фактический `sha1sum game/dota/gameinfo.gi` = **A0DC87ACC7A659EEDD1F9575EEE2BD3883E8F201** — совпадает. Значит это живой хеш-чек, а не декор. Любая правка этих файлов ломает самопроверку клиента; сообщество с 2022 года фиксирует баннеры/ошибки VAC после таких правок. **Вывод: путь «правка gameinfo» — красная линия, мы его не используем.**

Папка языка (`game/dota_russian`) в списке подписей отсутствует — она и есть легальный, «ванильный» механизм подмешивания контента (тот же, что возит озвучку).

### 2.8 Что говорит интернет (сверено 22.11.2026)

- Официальная документация Source2 Viewer по Dota 2 подтверждает раскладку путей и способ поиска модели героя через `scripts/npc/heroes/*.txt` — https://s2v.app/ValveResourceFormat/games/dota-2.html
- Публичный туториал по созданию скина повторяет ровно наш пайплайн: экспорт **компилированной** `.vmdl` из Viewer → переименование в базовую → упаковка VPK → папка игры (YouTube: «Road to creating Black ShadowFiend», шаги 1:1 совпадают).
- С 24.07.2026 аргумент `-language <что угодно>` больше не создаёт папку: путь берётся из `AudioLanguage` в `game/dota/cfg/boot.vcfg`; придуманные папки вроде `dota_tempcontent` не монтируются (проверено на месте: папка `dota_russian` + `boot.vcfg` = russian).
- Крупная волна банов (февраль 2024, кейс asdekor_r / Overplus) была за **внешний софт с инъекцией и скрытой статистикой**, а не за VPK-косметику. При этом ни один источник не даёт «100% гарантии» — формулировки и риски отражены в разделе 3.
- Экосистема конкурентов существует и большая: Dota 2 Mod Manager (h6rd), Minify, каталог D2PFX (1 500+ паков). Наше отличие — **узкий фокус на моделях + превью + дизайн + прозрачность**, а не «ещё один магазин паков».

## 3. Юридическая и античит-рамка (обязательный раздел для UI и маркетинга)

### 3.1 Что мы делаем

- Подменяем **байты визуальных ресурсов** в папке, которую Dota монтирует официально (`game/dota_<audio language>`).
- Не изменяем подписанные файлы, не патчим память, не внедряем DLL, не обходим проверки.
- Ничего не отправляем на сервер; сервер не знает о моде (он оперирует путями, не байтами).

### 3.2 Красные линии (жёсткие запреты в коде и в ревью)

| Запрещено | Почему |
|---|---|
| Правка `game/dota/gameinfo.gi` / `gameinfo_branchspecific.gi` / `dota.signatures` | ломает хеш-самопроверку клиента (2.7) |
| Правка `scripts/items/items_game.txt` ради «выдачи» предметов | schema-подмена, меняет экономику; исторически самый спорный механизм |
| Любая инъекция в `dota2.exe`, хуки, оверлеи, чтение памяти | это уже чит-класс, банится (кейс 2024) |
| Подмена карты, тумана, деревьев, травы, «видимости» | даёт игровое преимущество → читерство по определению Valve |
| Замена звуков противника/индикаторов способностей на «громче/раньше» | соревновательное преимущество |
| Скачивание и запуск чужих `.exe`/`.dll` из каталога | вредоносный вектор; каталог принимает только `.vpk` + картинки + манифест |
| Автопатч игры / обход Steam-целостности | выход за рамки клиентской косметики |

### 3.3 Формулировки для интерфейса (дисклеймер, показывается один раз и в «О программе»)

> WIBE CHANGER меняет только то, как игра выглядит **на вашем экране**. Другие игроки видят ванильные модели. Приложение не правит подписанные файлы игры, не внедряется в процесс Dota 2 и не даёт игрового преимущества. Использование любых сторонних модификаций — на ваш риск: Valve не публикует формальную политику по клиентской косметике, а обновления игры могут ломать моды.

### 3.4 Гигиена

- Не смешивать с читами/скриптами/оверлеями — «грязный» клиент = грязный бан.
- Один запуск в обычном (нерейтинговом) матче как smoke-тест перед рейтингом — рекомендация в onboarding.
- Не ставить моды, меняющие то, что видно противнику логически (модели героев можно, видимость — нет).

| C9 | HUD, иконки, курсоры, миникарта | `*.vcss_c`, `*.vtex_c` | `panorama/styles/…` (1 917), `panorama/images/…` (47 437), `panorama/images/cursors/…` | 49k+ | **A** | V1.5 |
| C10 | Звук: анонсеры, музыка, VO | `*.vsnd_c`, `*.vsndevts_c` | `sounds/vo/announcer/…`, `sounds/music/…` | 105 008 | **A** (с предупреждением про звуки противника) | V2 |
| C11 | Частицы и эффекты способностей | `*.vpcf_c` | `particles/units/heroes/hero_<h>/…`, `particles/econ/items/…` | 82 835 | **B** | V2 |

#### 4.1.2 Уровни риска и политика

- **A — разрешено.** Косметика, не влияющая на восприятие боя: тело и слоты героя, курьеры, варды, HUD/иконки/курсоры, музыка и анонсеры (с оговоркой: не менять звуки способностей противника на «ранние»/«громкие»).
- **B — разрешено с предупреждением и бейджем «не для рейтинга».** Строения, крипы, террейн-земля, частицы. Приложение показывает: «Меняет то, что видно в бою. Не даёт преимущества по правилам, но силуэты/читаемость меняются — решай сам». Пользователь может отключить бейдж в настройках, но он появляется при установке.
- **C — заблокировано на уровне кода.** Деревья, река, туман войны, трава, «прозрачность» моделей, что-либо меняющее видимость. Это ровно тот класс модов, из-за которого Valve в своё время отключила `-override_vpk` и ввела «белый список» (`-enable_addons`: HUD, иконки, VO). Список путей-запретов — константа в `SafetyPolicy`, импорт паков фильтруется по ней.

Правило симметрии для B-категорий: если меняется модель одной фракции (например, только Radiant-башня) — приложение требует парную замену для второй фракции либо предупреждает «одна сторона останется ванильной». Иначе игрок теряет ориентир «свой/чужой» — это уже влияние на игру.

#### 4.1.3 Технические особенности по категориям

**C3 Курьеры.** У курьера две модели: земная и `_flying` (56 из 160). Менять надо **обе**, иначе после апгрейда курьер «прыгает» в ванильную модель или в T-позу. Базовая модель по умолчанию — `models/courier/greevil/greevil.vmdl` (из `npc_units.txt`), не «donkey»: старые гайды врут. Манифест мода хранит пары `{ground, flying}`.

**C4 Строения.** Модели башен/бараков/трона задаются в `scripts/npc/npc_units.txt` (`tower_good`, `dire_tower002`, `radiant_ancient001`, `dire_barracks_melee001`, `outpost`…). Рядом лежат служебные модели (`*_destruction_lev1..3`, `*_glow`, `*_energy_effect`) — их **не трогаем**, иначе ломается анимация разрушения. Приложение берёт список целей из `npc_units.txt`, а не из хардкода.

**C5 Крипы.** У лейн-крипов 4+ варианта на фракцию (`melee`, `ranged`, `_mega`, `_flagbearer`, `_mega_flagbearer`), у нейтралов — свои. Если заменить только `melee`, получится «сборная солянка». Правило: мод либо покрывает все варианты, либо помечается `partial` и показывает, какие варианты остались ванильными.

**C6 Варды.** 109 моделей в `models/items/wards/`; sentry и observer используют одну модель варда. Безопасная категория, но предупреждать, если заменяются варды обеих сторон (визуально их и так различают по цвету — цвет менять не стоит).

**C7 Карта/террейн — единственная категория с двумя хранилищами:**
1. `maps/<terrain>_assets/…` — лежит в `pak01_dir.vpk` (обычная подмена, работает как всё остальное);
2. `maps/dota/worldnodes/…` — лежит в отдельном пакете `maps/dota.vpk` (1 040 файлов, 28.9 МБ). **Приоритет папки языка над пакетом карты не проверен** (R13). Пока это эксперимент: моды террейна помечаются `experimental`, для них обязателен A/B-тест и бэкап.

**C9 HUD/иконки.** `panorama/styles/*.vcss_c` (1 917) и `panorama/images/*.vtex_c` (47 437). Самый безопасный класс после героев, но самый хрупкий к патчам (Valve часто меняет разметку HUD) — обязательна проверка на совместимость после каждого патча.

**C10 Звук.** 105 008 файлов. Анонсеры/музыка — безопасно. Запрет: подмена звуков способностей/предупреждений противника (это уже информационное преимущество), поэтому категория проходит через `SafetyPolicy`.

**C11 Частицы.** 82 835 `*.vpcf_c`. Косметические эффекты — можно; всё, что упрощает чтение боя (убирает дым/вспышки/индикаторы) — блокируется по тем же правилам, что C8.

#### 4.1.4 Что это меняет в архитектуре

- В манифесте появляется `target.kind`: `hero.body`, `hero.slot`, `courier`, `tower`, `creep`, `ward`, `terrain`, `hud`, `sound`, `particles` (`hero` = `hero.body`, обратная совместимость).
- В Core появляется `SafetyPolicy` (белый/серый/чёрный список путей) и `CategoryProbe` — правила «полноты» на категорию (пары курьера, варианты крипов, пары фракций строений).
- В UI — левый рельс категорий с счётчиками и бейджами уровня риска; «Карта» — отдельный экран с превью террейна.
- В тестах — по одному golden-кейсу на категорию (курьер ground+flying, башня Radiant+Dire, крип 4 варианта, вард, HUD-иконка, террейн-эксперимент).
- В установке — «модпак» может содержать несколько категорий сразу (например, «зимний сет»: герой + курьер + башни).

## 5. Архитектура

### 5.1 Почему C# + Avalonia + ValveResourceFormat

- VRF (ValveResourceFormat, MIT) — **тот самый движок Source2 Viewer**: чтение/запись VPK v1/v2, декомпиляция моделей/материалов/текстур, экспорт glTF. Даёт нативную интеграцию вместо парсинга stdout.
- Avalonia 11 — кроссплатформенный, полностью кастомный дизайн (нам нужен «дорогой» вид), быстрый рендер, без WinUI-зависимостей.
- WebView2 + three.js — 3D-превью: экспорт `glb` из VRF и показ в изолированном вьюпорте (просто, красиво, управляемо). Запасной путь — Silk.NET/OpenGL.
- .NET 8 + `PublishSingleFile` + code signing → аккуратный установщик (MSIX или Inno Setup + signtool).
- `bin/Source2Viewer-CLI.exe` остаётся как **fallback**: если библиотека не умеет какой-то новый формат, вызываем CLI (он у нас уже протестирован).

### 5.2 Структура решения

```
WIBE_CHANGER_NEW/
  bin/                               внешние бинарники (CLI, dll) — не в git LFS, а в релизе
  docs/
    verification-log.md              лог проверок (команды + вывод)
    ui-reference.md                  скриншоты/референсы дизайна (опционально)
  src/
    WibeChanger.Core/                доменные модели, VPK, Steam, каталог, установка
      Domain/                        Hero, ModelAsset, Modpack, Manifest, PakSlot
      Steam/                         SteamLocator, LibraryFolders, BootConfig, BuildId
      Vpk/                           VpkReader, VpkWriter, VpkIndex, VrfAdapter, CliAdapter
      Assets/                        AssetScanner, ModelProbe, AnimValidator, GltfExport
      Mods/                          ModpackBuilder, Installer, ConflictResolver, Restore
      Catalog/                       HeroCatalog, ModelCatalog, PreviewCache
      Diagnostics/                   GameProcessGuard, IntegrityReport, Log
    WibeChanger.Cli/                 headless-команды (нужны для CI и для агента)
    WibeChanger.App/                 Avalonia UI
      Views/ ViewModels/ Controls/ Themes/ Assets/
  tests/
    WibeChanger.Core.Tests/          xUnit, юнит + интеграционные (sandbox-дерево игры)

  build/                             скрипты сборки, подписи, релиза
```

### 5.3 Слои и зависимости

```
UI (Avalonia)  ->  Application services (Core)  ->  VPK / Assets / Steam adapters  ->  файлы
                                \->  Cache (SQLite локально, %LOCALAPPDATA%\WibeChanger)
```

Правила:
- Core **не знает** про Avalonia; UI не лезет в файловую систему напрямую.
- Все файловые операции — через `IFileSystem`-абстракцию (тестируемость на sandbox-дереве).
- Никаких сетевых вызовов в V1 (каталог — локальный), значит нет телеметрии и приватности-проблем.
- Любая операция установки: **plan → validate → stage → commit → verify → journal**. Журнал в SQLite + `journal.json` рядом с папкой модов.

### 5.4 Поток данных при установке мода (happy path)

```
[1] Scan      -> Steam path, game path, AudioLanguage, buildid, занятые pak-слоты
[2] Choose    -> hero (из scripts/npc/heroes/*.txt), replacement model (из индекса пака)
[3] Probe     -> vmdl_c: анимации (>= N), скелет, attachment-имена, меши, материалы
[4] Build     -> staging/{models/heroes/axe/axe.vmdl_c} -> pakNN_dir.vpk (VRF)
[5] Validate  -> читаем свой VPK обратно, сверяем пути/CRC/размеры с ожидаемыми
[6] Commit    -> pakNN_dir.vpk + mod.json в %LOCALAPPDATA%\WibeChanger\library\<id>\
                 и линк в game/dota_russian/pakNN_dir.vpk (копия, не symlink)
[7] Journal   -> запись: id, файлы, buildid, время, хеши
[8] Done      -> UI: "Готово. Перезапусти Dota 2." + кнопка "Запустить игру"
```

### 5.5 Поток отката

```
uninstall(id) -> удалить pakNN_dir.vpk (проверив journal, что это наш файл)
              -> удалить запись из реестра
              -> если файл чужой/неизвестный: не трогать, показать предупреждение
restore_all() -> удалить ВСЕ паки из journal; опционально сравнить папку с эталоном Valve
```

## 6. Технический пайплайн (пошагово, с точными командами)

Все команды ниже выполнялись на этой машине (см. `docs/verification-log.md`).

### 6.1 Найти игру и папку модов

```powershell
# 1) Steam: HKCU\Software\Valve\Steam -> SteamPath
# 2) steamapps\libraryfolders.vdf -> пути библиотек
# 3) в каждой библиотеке: steamapps\appmanifest_570.acf -> installdir + buildid
# 4) игра: <library>\steamapps\common\<installdir>
# 5) аудио-язык: game\dota\cfg\boot.vcfg -> AudioLanguage
# 6) папка модов: game\ <AudioLanguage>   (например game\dota_russian)
#    Если AudioLanguage == english и папки нет -> предложить установить голосовой пак
#    или переключить язык озвучки (это настройка игры, не правка файлов).
```

Разбор `boot.vcfg` — обычный KeyValues2 (текст):

```
"boot"
{
	"AudioLanguage"		"russian"
	"UILanguage"		"russian"
}
```

Проверка, что пак реально монтируется: `game/dota/console.log` после запуска с `-condebug` содержит `[Filesystem] GAME` и `dota_language\pakNN.vpk`. Мод использует штатный языковой пак, поэтому `game/dota/gameinfo.gi` остаётся оригинальным и проходит проверку координатора.

### 6.2 Слоты pak

- `pak01` в папке языка — **голоса Valve**, трогать нельзя.
- `pak02..pak99` — свободные слоты модов. Держать `pak64` свободным без нужды (используется Mod Manager для notice).
- Считать занятыми все существующие `<...>_dir.vpk` + их чанки.
- Спорный вопрос (проверить в игре, см. 16.4): при двух модах с одинаковым файлом побеждает **младший номер** (по документации 2026 г.). В приложении заложить «порядок» как сортируемое поле и self-test.

Проверенный список в этой установке: `pak01,02,03,04,05,64` → первый свободный **06**.

### 6.3 Индексация пака игры

```powershell
bin\Source2Viewer-CLI.exe -i "Z:\Steam\steamapps\common\dota 2 beta\game\dota\pak01_dir.vpk" --vpk_list > pak01_list.txt
# 388 776 строк, ~1.9 с
```

В приложении: `VrfAdapter.ListPackage()` (быстро, в памяти) + кеш в SQLite (ключ = buildid + mtime пака). Индексировать **только нужные префиксы**:

```
models/heroes/            база
models/items/             косметика
materials/models/         материалы
particles/                эффекты
panorama/images/          иконки
scripts/npc/heroes/       карта героев
resource/localization/    имена
```

### 6.4 Карта «герой → модель»

```powershell
bin\Source2Viewer-CLI.exe -i ...\pak01_dir.vpk -f "scripts/npc/heroes/" -o .\heroes
# 129 файлов; в каждом: "Model" "models/heroes/<hero>/<hero>.vmdl"
# всего 142 Model (включая персона-варианты)
```

Парсинг: KeyValues1 (тот же синтаксис, что у `npc_heroes.txt`). Дополнительно брать:
- `workshop_guide_name` → отображаемое имя;
- `HeroID` / `HeroOrderID` → порядок в сетке;
- `Persona` → список персон героя (готовые цели для замены);
- `particle_folder`, `GameSoundsFile` → будущие фичи V2.

### 6.5 Поиск «полных» моделей-кандидатов

Критерий полной модели (годится на место тела героя):
1. путь начинается с `models/heroes/` или лежит в `models/items/<hero>/...`;
2. имя содержит `_base`, `persona`, `arcana`, `_v2`, `_alt`, или модель перечислена в `Persona`;
3. **главное**: в декомпилированном `*.vmdl` есть `AnimationList` с ≥ 60 `AnimFile` и `AttachmentList` с `attach_mouth`/`attach_attack1`.

Проверенные примеры: `models/items/axe/axe_carnival/axe_carnival_base.vmdl_c` (81 анимация, 1.3 МБ). Базовая модель Axe — 78 файлов декомпиляции, 604 КБ.

Оптимизация: не декомпилировать 1 718 моделей целиком. Читать из `vmdl_c` только блок данных через VRF (`--block`) / библиотечный `Model` API: количество анимаций, имена аттачментов, список материалов. Кеш в SQLite: `(path, crc, animCount, attachments, ok)`.

### 6.6 Превью (3D)

```powershell
bin\Source2Viewer-CLI.exe -i <vpk> -f "models/items/axe/axe_carnival/axe_carnival_base.vmdl_c" `
    -o .\preview --gltf_export_format glb --gltf_export_materials
# ~1.3 с на модель, отдаёт axe_carnival_base.glb (+ *_physics.glb)
```

В приложении:
- экспорт один раз → кеш `%LOCALAPPDATA%\WibeChanger\previews\<crc>.glb`;
- three.js (`GLTFLoader`, `OrbitControls`, `RoomEnvironment`, ACES tone mapping), фон-градиент, медный rim-light;
- анимация idle (если в glb есть клипы — брать первый `idle`/`run`), кнопки «крутить/анимация/каркас»;
- фолбэк без WebView2 — статичный PNG из первого кадра (рендер offscreen не обязателен: показываем иконку героя).


### 6.7 Сборка мода (VPK)

Стадии в staging-папке:

```
staging/
  models/heroes/axe/axe.vmdl_c              <- байты выбранной модели (переименованной)
  # опционально:
  models/heroes/axe/axe_weapon.vmdl_c       <- нуль-модель, чтобы снять дефолтное оружие
  materials/models/heroes/axe/*.vmat_c      <- если пак принёс материалы
  wibe/manifest.json                        <- копия манифеста внутрь пака
```

Упаковка:

```powershell
bin\Source2Viewer-CLI.exe -i .\staging --vpk_create .\pak06_dir.vpk
# для паков > 1 ГБ: --vpk_create_chunk_size 1024 (тогда имя обязано быть *_dir.vpk)
```

Правила, которые нельзя нарушать:

- пути внутри VPK — **строго lowercase**, ровно как в ванильном паке, без ведущего слэша;
- имя файла: `pak<NN>_dir.vpk`, NN двузначный (`06`..`99`);
- не ставить файлы, которые игра не грузит (например `.dmx`) — только `*_c`-ресурсы; мусор не вредит, но раздувает пак;
- после сборки — **обратная проверка**: открыть свой VPK, сверить `(path, crc, size)` с ожидаемым списком; при расхождении установку отменить;
- предупреждать, если пак > 1.5 ГБ (модели обычно 5–150 МБ).

### 6.8 Установка и откат

- Копирование (не symlink, не hardlink) в `game\<audio>\pakNN_dir.vpk`.
- Атомарность: пишем `pakNN_dir.vpk.tmp` в той же папке → `File.Move(tmp, final)`. Слот бронируем **до** записи (файл-замок), чтобы два мода не сели в один номер.
- Игра запущена? Разрешать установку, но предупредить: «изменения применятся после полного перезапуска Dota 2» (папка читается один раз на старте). При удалении файл может быть занят — retry 10 раз по 200/500/1000 мс, затем внятная ошибка.
- Никогда не удалять `pakNN_dir.vpk`, которых нет в нашем журнале.
- Права: если игра в `C:\Program Files`, запись требует elevation → показать объяснение и кнопку «Перезапустить с правами администратора» (манифест `requireAdministrator` только для этой операции, не для всего приложения).

### 6.9 После патча Dota

Признаки проблемы: изменился `buildid`, наши паки исчезли из папки, изменился CRC ванильных моделей.

Алгоритм восстановления:

1. **Integrity scan**: сверить журнал с диском → `missing | outdated | ok`.
2. Баннер: «Dota 2 обновилась: 7 модов нужно вернуть» → кнопка **Rebuild all**.
3. Пересборка из локальной библиотеки (наши VPK не зависят от ванильных байтов, поэтому чаще всего достаточно скопировать файл обратно).
4. Если модель-источник исчезла из пака Valve (удалили скин) → мод помечается `unavailable`, предлагается удалить или заменить.
5. Если изменилась папка аудио-языка (пользователь сменил озвучку) → баннер «Моды лежат в старой папке» + кнопка **Move** (переносит наши паки в новую папку по журналу).

```json
  "capabilities": {
    "animations": 81,
    "attachments": ["attach_mouth", "attach_attack1", "attach_attack2"],
    "materials": 6
  },
  "preview": { "glb": "previews/5890d3a8.glb", "image": "previews/5890d3a8.webp" },
  "requirements": { "minBuildId": 26825343 },
  "notes": "Меняется только тело; дефолтное оружие/броня остаются."
}
```

Правила:

- `id` — slug, глобально уникальный; `version` — semver;
- `target.kind` — одно из: `hero.body`, `hero.slot`, `courier`, `tower`, `creep`, `ward`, `terrain`, `hud`, `sound`, `particles` (см. 4.1);
- `replaces[].path` — **единственный** источник правды для конфликтов и отката;
- `source.crc` — контроль актуальности после патча;
- для `courier` обязательна пара `{ground, flying}`; для `tower`/`creep` — `variants[]` и `factions[]` (см. 4.1.3); для `terrain` — `roots[]` (какие каталоги карты заменяются) и флаг `experimental`;
- строгая валидация JSON Schema (`additionalProperties: false`), понятные ошибки на русском;
- `schema` версионируется; миграции манифестов — обязательны.

### 7.1 Конфликты

Два мода конфликтуют, если пересекаются `replaces[].path`. UI: карта конфликтов, «кто победил по слоту», кнопка «переставить приоритет» (пересобрать паки с другими номерами). Никаких тихих перезаписей: при установке мод, который проиграет конфликт, помечается `overruled` с перечнем проигранных файлов.

## 8. Модель данных (SQLite, локально)

```sql
CREATE TABLE install(              -- что установлено в игру
  id TEXT PRIMARY KEY, pak INTEGER, path TEXT NOT NULL,
  buildid TEXT, audio TEXT, created_at TEXT, state TEXT
);

CREATE TABLE asset(                -- индекс ассетов на buildid
  path TEXT, kind TEXT, crc TEXT, size INTEGER,
  anim_count INTEGER, has_mouth INTEGER, materials INTEGER,
  name TEXT, buildid TEXT,
  PRIMARY KEY(path, buildid)
);

CREATE VIRTUAL TABLE asset_fts USING fts5(path, name);

CREATE TABLE journal(              -- журнал операций (аудит + откат)
  seq INTEGER PRIMARY KEY AUTOINCREMENT,
  ts TEXT, op TEXT, id TEXT, payload TEXT
);
```

Каталог строится один раз на `buildid`: скан `models/heroes/*` и `models/items/*` (только `*.vmdl_c`) → probe → запись в `asset`. Бюджет прогрева: ≤ 90 с однократно на 1 700 моделей (8 потоков), далее мгновенно из кеша. Кеш живёт в `%LOCALAPPDATA%\WibeChanger\cache.db` и сбрасывается при смене buildid.

1. **Onboarding (3 шага, 1 раз)**
   - «Нашли Dota 2: Z:\...\dota 2 beta, сборка 26825343, озвучка: русская → папка dota_russian, свободный слот pak06»;

   - drag&drop `.vpk` / `.zip` / папки с `*.vmdl_c`;

4.2 **Строения и Крипы**
   - для строений — две колонки `Radiant / Dire` с требованием парной замены;

- Никаких модальных окон без выхода (Esc всегда работает), никаких блокирующих «ОК» после каждой операции.

## 11. Надёжность, производительность, безопасность приложения

### 11.1 Бюджеты производительности

| Операция | Бюджет |
|---|---|
| Холодный старт до интерактивного UI | ≤ 2.0 с |
| Определение установки + слотов | ≤ 150 мс |
| Полный список пака (388 к файлов) | ≤ 2.5 с (факт: 1.9 с через CLI) |
| Прогрев индекса моделей (1 700 шт.) | ≤ 90 с, кеш → ≤ 1 с |
| Превью одной модели (glb) | ≤ 2.5 с (факт: 1.3 с), кеш → ≤ 100 мс |
| Сборка VPK на 1 модель | ≤ 1.5 с |
| Установка (копирование) | ≤ 300 мс на 100 МБ |
| Память при простое | ≤ 400 МБ |
| Размер установщика | ≤ 45 МБ (без внешних бинарников), CLI-пак — отдельным опциональным компонентом |

### 11.2 Надёжность

- Все операции идемпотентны: повторный запуск установки не создаёт дублей.
- Каждая запись — в журнал **до** изменения на диске (write-ahead), после — статус.
- «Грязное» состояние (крэш в середине) чинится при следующем старте: `journal.state = pending` → rollback или finish.
- Никогда не писать вне: папки модов игры, `%APPDATA%\WibeChanger`, `%LOCALAPPDATA%\WibeChanger`, временной папки приложения.
- Sandbox-режим для тестов: подмена корня игры на временную папку (`WIBE_GAME_ROOT` env var).

### 11.3 Безопасность приложения

- Подпись кода (EV/OV сертификат) для `.exe`/установщика; публикация SHA-256 в релизе.
- Никакого `eval`, никаких загрузок и запусков исполняемых файлов из каталога.
- Импорт пака — только чтение; распаковка в изолированную папку; лимиты (размер, число файлов, длина путей) против zip-бомб.
- Проверка путей на zip-slip (`..`, абсолютные пути, диски, UNC).
- Логи не содержат путей пользователя по умолчанию (опция «подробные логи»).
- Никакой телеметрии по умолчанию; обновления — только с проверкой подписи.

## 13. Тестирование

### 13.1 Уровни

1. **Unit** (Core): парсер KeyValues (`boot.vcfg`, `npc_dota_hero_*.txt`), выбор слота, конфликты, валидация манифеста, санитайзер путей.
2. **Integration (sandbox)**: фейковое дерево игры во временной папке (папки, `pakNN`, `boot.vcfg`, `appmanifest`), прогон install/uninstall/restore/rebuild. Обязательные кейсы:
   - свободных слотов нет → понятная ошибка;
   - файл занят (эмуляция) → retry, затем ошибка;
   - крэш между staging и commit → авто-rollback;
   - два мода на один путь → корректный `overruled`;
   - импорт VPK с `scripts/` → блокировка;
   - zip-slip имена → блокировка.
3. **Golden** (только на машине с Dota 2, `[Trait("Category","Game")]`): чтение реального `pak01_dir.vpk`, поиск модели Axe, сборка VPK, обратное чтение, сверка CRC с игрой.
4. **Property-based**: round-trip VPK (create → read → equal), для случайных наборов путей и размеров.
5. **UI (headless Avalonia)**: навигация, состояния, локализация, отсутствие исключений на пустом каталоге.
6. **Регресс на патч**: при смене `buildid` — тест «индекс пересобирается, старый кеш не используется».

### 13.2 Протокол проверки в игре (обязателен перед релизом)

1. **Workshop Tools (безопасно, офлайн)**: открыть `hero_demo`, проверить, что модель грузится, анимации играют, аттачменты на месте. Фиксировать: T-поза, «прыгающие» части, отсутствие текстур.
2. **Обычный матч (unranked/bot)**: убедиться, что модель видна только у себя, нет ошибок в консоли (`-console`), нет рассинхронов.
3. **Рейтинг**: только после успешных шагов 1–2. Один матч, наблюдение за: загрузка (нет «missing model»), способности/эффекты, производительность (FPS в норме ±3 %).
4. **Откат**: «Откатить всё» → перезапуск → ванильный вид. Проверить, что в папке не осталось наших файлов.
5. **Патч-симуляция**: удалить `pakNN` вручную → запустить приложение → баннер восстановления → Rebuild all.

Чек-лист оформляется как `docs/qa-in-game.md` и заполняется на каждом релизе (модель, герой, ОС, buildid).

### 13.3 Матрица тестируемых моделей (минимум для V1)

| Кейс | Пример | Что проверяем |
|---|---|---|
| Полная модель-аркана | `models/items/axe/axe_carnival/axe_carnival_base.vmdl_c` | анимации, аттачменты |
| Персона | любая `Persona` из `npc_dota_hero_*.txt` | скелет, масштаб |
| Базовая модель как «ваниль» | `models/heroes/axe/axe.vmdl_c` | откат |
| Модель без анимаций (негатив) | любая деталь (belt) | приложение должно предупредить и не ставить |
| Нуль-модель | `models/development/invisiblebox.vmdl_c` | «снять слот» (проверить визуально) |

## 15. Definition of Done и метрики

### Критерии приёмки V1

1. Приложение находит игру без ручного ввода пути (и позволяет ввести вручную).
2. Hero grid показывает всех героев с портретами и статусом модов.
3. 3D-превью открывается ≤ 2.5 с (кеш ≤ 300 мс) и корректно для 10 разных героев.
4. Установка «Axe — Carnival» на чистой игре работает и видна в игре.
5. «Откатить всё» возвращает ваниль, в папке модов не остаётся наших файлов.
6. Импорт стороннего `.vpk` с косметикой работает; `.vpk` со `scripts/` — блокируется с объяснением.
7. Конфликты показываются до установки, а не после.
8. Симуляция патча (удаление паков) лечится кнопкой.
9. Ни одна операция не пишет вне разрешённых папок (проверено тестом).
10. Локализация RU/EN, ошибки на человеческом языке, никаких стектрейсов в UI.
11. Тесты: Core coverage ≥ 70 %, интеграционные зелёные, golden на реальной игре зелёные.
12. Чек-лист in-game (13.2) заполнен; откат проверен в игре.

### Метрики качества (цель)

| Метрика | Цель |
|---|---|
| Крэши на 100 сессий | < 1 |
| «Мод не появился в игре» (по логам) | < 2 % установок |
| Время до первой установки у нового пользователя | < 90 с |
| Доля успешных Rebuild после патча | > 98 % |
| Средний размер мода | 5–80 МБ |
